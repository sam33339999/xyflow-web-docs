# 常見錯誤

import { Callout } from 'nextra/components';

本指南包含使用 React Flow 時可能出現的警告和錯誤。我們也會新增從我們的 [Discord 伺服器](https://discord.gg/RVmnytFmGW)、[Github Issues](https://github.com/xyflow/xyflow/issues) 和 [Github Discussions](https://github.com/xyflow/xyflow/discussions) 收集到的常見問題和陷阱。

### 警告：似乎你沒有將 zustand provider 用作祖先元件。

這通常發生在以下情況：

**A：** 你安裝了兩個不同版本的 @reactflow/core。<br /> **B：** 你試圖在 React Flow context 外部存取內部 React Flow 狀態。

#### 解決方案 A

更新 reactflow 和 @reactflow/node-resizer（如果你正在使用它），移除 node_modules 和 package-lock.json 並重新安裝依賴項。

#### 解決方案 B

一個可能的解決方案是使用 [`<ReactFlowProvider />`](/api-reference/react-flow-provider) 包裝你的元件，或將存取狀態的程式碼移動到你的 React Flow 實例的子元件內部。

<Callout type="error">這會導致錯誤：</Callout>

```jsx
import { ReactFlow } from '@xyflow/react';
import '@xyflow/react/dist/style.css';

function FlowWithoutProvider(props) {
  // cannot access the state here
  const reactFlowInstance = useReactFlow();

  return <ReactFlow {...props} />;
}

export default FlowWithoutProvider;
```

<Callout type="error">這也會導致錯誤：</Callout>

```jsx
import { ReactFlow, ReactFlowProvider } from '@xyflow/react';
import '@xyflow/react/dist/style.css';

function Flow(props) {
  // still cannot access the state here
  // only child components of this component can access the state
  const reactFlowInstance = useReactFlow();

  return (
    <ReactFlowProvider>
      <ReactFlow {...props} />
    </ReactFlowProvider>
  );
}

export default FlowWithProvider;
```

<Callout type="info">這個可以運作：</Callout>

當你想要存取 React Flow 的內部狀態時（例如使用 `useReactFlow` hook），你需要使用 `<ReactFlowProvider />` 包裝你的元件。這裡的包裝是在元件外部完成的：

```jsx
import { ReactFlow, ReactFlowProvider } from '@xyflow/react';
import '@xyflow/react/dist/style.css';

function Flow(props) {
  // you can access the internal state here
  const reactFlowInstance = useReactFlow();

  return <ReactFlow {...props} />;
}

// wrapping with ReactFlowProvider is done outside of the component
function FlowWithProvider(props) {
  return (
    <ReactFlowProvider>
      <Flow {...props} />
    </ReactFlowProvider>
  );
}

export default FlowWithProvider;
```

### 看起來你建立了一個新的 nodeTypes 或 edgeTypes 物件。

如果這不是故意的，請在元件外部定義 nodeTypes/edgeTypes 或將它們記憶化。

當 `nodeTypes` 或 `edgeTypes` 屬性在初始渲染後發生變更時，會出現此警告。`nodeTypes` 或 `edgeTypes` 只應在非常罕見的情況下動態變更。通常，它們會與你在應用程式中使用的所有類型一起定義一次。很容易發生的情況是你在元件渲染函式內部定義 nodeTypes 或 edgeTypes 物件，這會導致每次元件重新渲染時 React Flow 都會重新渲染。

<Callout type="error">會導致警告：</Callout>

```jsx
import { ReactFlow } from '@xyflow/react';
import '@xyflow/react/dist/style.css';

import MyCustomNode from './MyCustomNode';

function Flow(props) {
  // new object being created on every render
  // causing unnecessary re-renders
  const nodeTypes = {
    myCustomNode: MyCustomNode,
  };

  return <ReactFlow nodeTypes={nodeTypes} />;
}

export default Flow;
```

<Callout type="info">建議的實作方式：</Callout>

```jsx
import { ReactFlow } from '@xyflow/react';
import MyCustomNode from './MyCustomNode';

// defined outside of the component
const nodeTypes = {
  myCustomNode: MyCustomNode,
};

function Flow(props) {
  return <ReactFlow nodeTypes={nodeTypes} />;
}

export default Flow;
```

<Callout type="info">替代實作方式：</Callout>

如果你想要動態變更 nodeTypes 而不導致不必要的重新渲染，可以使用這個方法。

```jsx
import { useMemo } from 'react';
import { ReactFlow } from '@xyflow/react';
import '@xyflow/react/dist/style.css';

import MyCustomNode from './MyCustomNode';

function Flow(props) {
  const nodeTypes = useMemo(
    () => ({
      myCustomNode: MyCustomNode,
    }),
    [],
  );

  return <ReactFlow nodeTypes={nodeTypes} />;
}

export default Flow;
```

### 找不到節點類型。使用後備類型 "default"。

這通常發生在你為某個節點指定自訂節點類型，但沒有將正確的 nodeTypes 屬性傳遞給 React Flow 時。自訂節點的 type 選項字串需要與 nodeTypes 物件的鍵完全相同。

<Callout type="error">無法運作：</Callout>

```jsx
import { ReactFlow } from '@xyflow/react';
import '@xyflow/react/dist/style.css';

import MyCustomNode from './MyCustomNode';

const nodes = [
  {
    id: 'mycustomnode',
    type: 'custom',
    // ...
  },
];

function Flow(props) {
  // nodeTypes property is missing, so React Flow cannot find the custom node component to render
  return <ReactFlow nodes={nodes} />;
}
```

<Callout type="error">這個也無法運作：</Callout>

```jsx
import { ReactFlow } from '@xyflow/react';
import '@xyflow/react/dist/style.css';

import MyCustomNode from './MyCustomNode';

const nodes = [
  {
    id: 'mycustomnode',
    type: 'custom',
    // ...
  },
];

const nodeTypes = {
  Custom: MyCustomNode,
};

function Flow(props) {
  // node.type and key in nodeTypes object are not exactly the same (capitalized)
  return <ReactFlow nodes={nodes} nodeTypes={nodeTypes} />;
}
```

<Callout type="info">這個可以運作：</Callout>

```jsx
import { ReactFlow } from '@xyflow/react';
import '@xyflow/react/dist/style.css';

import MyCustomNode from './MyCustomNode';

const nodes = [
  {
    id: 'mycustomnode',
    type: 'custom',
    // ...
  },
];

const nodeTypes = {
  custom: MyCustomNode,
};

function Flow(props) {
  return <ReactFlow nodes={nodes} nodeTypes={nodeTypes} />;
}
```

### React Flow 父容器需要寬度和高度來渲染圖形。

在底層，React Flow 會測量父 DOM 元素以調整渲染器。如果你嘗試在沒有高度的普通 div 中渲染 React Flow，我們無法顯示圖形。如果你遇到此警告，需要確保你的包裝元件附加了一些 CSS，使其獲得固定高度或繼承其父元素的高度。

<Callout type="error">這會導致警告：</Callout>

```jsx
import { ReactFlow } from '@xyflow/react';
import '@xyflow/react/dist/style.css';

function Flow(props) {
  return (
    <div>
      <ReactFlow {...props} />
    </div>
  );
}
```

<Callout type="info">可運作的範例：</Callout>

```jsx
import { ReactFlow } from '@xyflow/react';

function Flow(props) {
  return (
    <div style={{ height: 800 }}>
      <ReactFlow {...props} />
    </div>
  );
}
```

### 只有子節點可以使用父節點範圍。

當你嘗試將 `extent` 選項新增到沒有父節點的節點時，會出現此警告。根據你想做的事情，你可以移除 `extent` 選項或指定 `parentNode`。

<Callout type="error">會顯示警告：</Callout>

```jsx
import { ReactFlow } from '@xyflow/react';
import '@xyflow/react/dist/style.css';

const nodes = [
  {
    id: 'mycustomnode',
    extent: 'parent',
    // ...
  },
];

function Flow(props) {
  return <ReactFlow nodes={nodes} />;
}
```

<Callout type="info">Warning resolved:</Callout>

```jsx import { ReactFlow } from '@xyflow/react';
const nodes = [
  {
    id: 'mycustomnode',
    parentNode: 'someothernode',
    extent: 'parent',
    // ...
  },
];

function Flow(props) {
  return <ReactFlow nodes={nodes} />;
}
```

### 無法建立連線。連線需要來源和目標。

當你沒有將 `source` 和 `target` 選項傳遞給連線物件時，就會發生這種情況。沒有來源和目標，連線無法渲染。

<Callout type="error">會顯示警告：</Callout>

```jsx
import { ReactFlow } from '@xyflow/react';
import '@xyflow/react/dist/style.css';

const nodes = [
  /* ... */
];

const edges = [
  {
    nosource: '1',
    notarget: '2',
  },
];

function Flow(props) {
  return <ReactFlow nodes={nodes} edges={edges} />;
}
```

<Callout type="info">這個可以運作：</Callout>

```jsx
import { ReactFlow } from '@xyflow/react';

const nodes = [
  /* ... */
];

const edges = [
  {
    source: '1',
    target: '2',
  },
];

function Flow(props) {
  return <ReactFlow nodes={nodes} edges={edges} />;
}
```

### id="some-id" 的舊連線不存在。

當你嘗試[重新連接連線](/examples/edges/reconnect-edge)，但你想要更新的連線已從狀態中移除時，就會發生這種情況。這是非常罕見的情況。請參閱[重新連接連線範例](/examples/edges/reconnect-edge)以了解實作細節。

### 無法為來源/目標控制點 id: "some-id" 建立連線；連線 id: "some-id"。

如果你正在使用多個控制點，並且無法透過其 `id` 屬性找到控制點，或者你沒有在以程式方式[新增或移除控制點後更新節點內部](/api-reference/hooks/use-update-node-internals)，就會發生這種情況。請參閱[自訂節點範例](/examples/nodes/custom-node)以了解使用多個控制點的範例。

### 使用 webpack 4 建置應用程式時出現錯誤。

如果你使用 webpack 4，可能會遇到這樣的錯誤：

```
ERROR in /node_modules/@reactflow/core/dist/esm/index.js 16:19
Module parse failed: Unexpected token (16:19)
You may need an appropriate loader to handle this file type, currently no loaders are configured to process this file. See https://webpack.js.org/concepts#loaders
```

React Flow 是一個現代 JavaScript 程式碼庫，使用了許多較新的 JavaScript 功能。預設情況下，webpack 4 不會轉譯你的程式碼，也不知道如何處理 React Flow。

你需要在 webpack 配置中新增一些 babel 外掛來使其運作：

```sh npm2yarn copy
npm i --save-dev babel-loader@8.2.5 @babel/preset-env @babel/preset-react @babel/plugin-proposal-optional-chaining @babel/plugin-proposal-nullish-coalescing-operator
```

並像這樣配置載入器：

```js
{
  test: /node_modules[\/\\]@?reactflow[\/\\].*.js$/,
  use: {
    loader: 'babel-loader',
    options: {
      presets: ['@babel/preset-env', "@babel/preset-react"],
      plugins: [
        "@babel/plugin-proposal-optional-chaining",
        "@babel/plugin-proposal-nullish-coalescing-operator",
      ]
    }
  }
}
```

<Callout type="info">
  如果你使用 webpack 5，你不需要做任何事情！React Flow 可以直接使用。
</Callout>

### 當我的節點包含 `<canvas />` 元素時，滑鼠事件無法正常運作。

如果你在自訂節點內部使用 `<canvas />` 元素，你可能會遇到來自 canvas 的滑鼠事件座標看似不正確的問題。

React Flow 使用 CSS 轉換來在放大和縮小時縮放節點。然而，從 DOM 的角度來看，元素的大小仍然相同。如果你有事件監聽器想要計算相對於 canvas 元素的滑鼠位置，這可能會導致問題。

要在你控制的事件處理程序中解決這個問題，你可以將計算出的相對位置乘以 `1 / zoom`，其中 `zoom` 是流程的當前縮放級別。要取得當前縮放級別，你可以使用 [`useReactFlow`](/api-reference/hooks/use-react-flow) hook 中的 `getZoom` 方法。

### 連線未顯示。

如果你的連線未在 React Flow 中顯示，這可能是由於以下原因之一：

- 你沒有匯入 React Flow 樣式表。如果你沒有匯入它，可以像這樣匯入：`import '@xyflow/react/dist/style.css';`。
- 如果你用自訂節點取代了預設節點，請檢查該自訂節點在自訂節點元件中是否有適當的 `source/target` 控制點。沒有控制點就無法建立連線。
- 如果你使用外部樣式函式庫（如 Tailwind 或 Bulma），請確保它不會覆蓋連線樣式。例如，有時樣式函式庫會使用 `overflow: hidden` 覆蓋 `.react-flow__edges` SVG 選擇器，這會隱藏連線。
- 如果你使用非同步操作（如向後端發送請求），請確保在非同步操作後呼叫 [`useUpdateNodeInternal`](/api-reference/hooks/use-update-node-internals) hook 回傳的 `updateNodeInternals` 函式，這樣 React Flow 才能在內部更新控制點位置。

### 連線顯示不正確。

如果你的連線未按預期渲染，這可能是由於以下原因之一：

- 如果你想隱藏控制點，不要使用 `display: none` 來隱藏它們。請使用 `opacity: 0` 或 `visibility: hidden`。
- 如果連線未連接到正確的控制點，請檢查你是否在自訂節點元件中新增了多個相同類型（`source` 或 `target`）的控制點。如果是這種情況，請為它們分配 ID。節點上相同類型的多個控制點需要有可區分的 ID，這樣 React Flow 才能知道連線對應哪個控制點。
- 如果你正在變更控制點的位置（透過重新排序等），請確保之後呼叫 [`useUpdateNodeInternals`](/api-reference/hooks/use-update-node-internals) hook 回傳的 `updateNodeInternals` 函式，這樣 React Flow 才能知道要在內部更新控制點位置。
- 如果你使用自訂連線，並希望連線從來源控制點到目標控制點，請確保正確傳遞你從自訂連線元件獲得的 `sourceX、sourceY、targetX 和 targetY` props 到連線路徑建立函式中（例如 [`getBezierPath`](/api-reference/utils/get-bezier-path) 等）。`sourceX, sourceY` 和 `targetX, targetY` 分別代表來源和目標控制點的 `x,y` 座標。
- 如果自訂連線的來源或目標側未如預期朝向控制點（以奇怪的角度進入或退出控制點），請確保將你從自訂連線元件獲得的 `sourcePosition` 和 `targetPosition` props 傳遞到連線路徑建立函式中（例如 [`getBezierPath`](/api-reference/utils/get-bezier-path)）。在路徑建立函式中傳遞來源/目標控制點位置對於連線在控制點正確開始或結束是必要的。
