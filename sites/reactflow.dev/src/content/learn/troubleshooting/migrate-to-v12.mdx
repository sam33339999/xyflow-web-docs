# 遷移到 React Flow 12

import { Callout } from 'nextra/components';

<Callout type="info">
  你可以在這裡找到舊版本 React Flow 的文件：
  [v11](https://v11.reactflow.dev)、[v10](https://v10.reactflow.dev)、
  [v9](https://v9.reactflow.dev)
</Callout>

在你可以使用 React Flow 12 附帶的**[新功能](#new-features)**（如伺服器端渲染、計算流程和深色模式）之前，這裡是你需要先處理的重大變更。我們試圖將重大變更保持在最低限度，但其中一些是實作新功能所必需的。

## 遷移指南

在開始遷移之前，你需要安裝新套件。

```bash npm2yarn
npm install @xyflow/react
```

### 1. 新的 npm 套件名稱

套件 `reactflow` 已重新命名為 `@xyflow/react`，並且不再是預設匯入。你還需要調整樣式匯入。在 v12 之前，React Flow 被分為多個套件。現在不再是這樣了。如果你只使用核心，現在需要安裝 `@xyflow/react` 套件。

**舊 API**

```js
// npm install reactflow
import ReactFlow from 'reactflow';
```

**新 API**

```js
// npm install @xyflow/react
import { ReactFlow } from '@xyflow/react';

// you also need to adjust the style import
import '@xyflow/react/dist/style.css';

// or if you just want basic styles
import '@xyflow/react/dist/base.css';
```

### 2. 節點的 <code>measured</code> 屬性用於測量的 <code>width</code> 和 <code>height</code>

所有測量的節點值現在都儲存在 `node.measured` 中。除了新的套件名稱，這是最大的變更。在 React Flow 測量你的節點後，它會將尺寸寫入 `node.measured.width` 和 `node.measured.height`。如果你使用任何版面配置函式庫（如 dagre 或 elk），現在需要從 `node.measured` 而不是 `node` 取得尺寸。如果你使用 `width` 和 `height`，這些值現在將用作內聯樣式來指定節點尺寸。

**舊 API**

```js
// getting the measured width and height
const nodeWidth = node.width;
const nodeHeight = node.height;
```

**新 API**

```js
// getting the measured width and height
const nodeWidth = node.measured?.width;
const nodeHeight = node.measured?.height;
```

### 3. 新的尺寸處理 <code>node.width</code> / <code>node.height</code> 與 <code>node.measured.width</code> / <code>node.measured.height</code>

為了支援伺服器端渲染，我們必須稍微重組 API，以便使用者更輕鬆地傳遞節點尺寸。為此，我們變更了 `node.width` 和 `node.height` 屬性的行為。在 React Flow 11 中，這些屬性是測量值，僅用作參考。在 React Flow 12 中，這些屬性用作內聯樣式來指定節點尺寸。如果你從資料庫載入節點，可能想要從節點中移除 `width` 和 `height` 屬性，因為現在的行為略有不同。現在使用 `width` 和 `height` 意味著尺寸不是根據內容動態調整，而是固定的。

**Old API**

```js
// in React Flow 11 you might have used node.style to set the dimensions
const nodes = [
  {
    id: '1',
    type: 'input',
    data: { label: 'input node' },
    position: { x: 250, y: 5 },
    style: { width: 180, height: 40 },
  },
];
```

**New API**

```js
// in React Flow 12 you can used node.width and node.height to set the dimensions
const nodes = [
  {
    id: '1',
    type: 'input',
    data: { label: 'input node' },
    position: { x: 250, y: 5 },
    width: 180,
    height: 40,
  },
];
```

如果你想了解更多關於如何為伺服器端渲染配置 React Flow，可以閱讀[伺服器端渲染指南](/learn/advanced-use/ssr-ssg-configuration)。

### 4. 更新節點和連線

我們不再支援透過物件變更來更新節點和連線。如果你想更新某個屬性，需要建立新的節點/連線。

**舊 API**

```js
setNodes((currentNodes) =>
  currentNodes.map((node) => {
    node.hidden = true;
    return node;
  }),
);
```

**新 API**

```js
setNodes((currentNodes) =>
  currentNodes.map((node) => ({
    ...node,
    hidden: true,
  })),
);
```

### 5. 將 <code>onEdgeUpdate</code>（及相關 API）重新命名為 <code>onReconnect</code>

我們將 `onEdgeUpdate` 函式重新命名為 `onReconnect`，並將所有相關 API（如下所述）一併重新命名。新名稱更具描述性，清楚地表明該函式用於重新連接連線。

- `updateEdge` 重新命名為 `reconnectEdge`
- `onEdgeUpdateStart` 重新命名為 `onReconnectStart`
- `onEdgeUpdate` 重新命名為 `onReconnect`
- `onEdgeUpdateEnd` 重新命名為 `onReconnectEnd`
- `edgeUpdaterRadius` 重新命名為 `reconnectRadius`
- `edge.updatable` 重新命名為 `edge.reconnectable`
- `edgesUpdatable` 重新命名為 `edgesReconnectable`

**舊 API**

```js
<ReactFlow
  onEdgeUpdate={onEdgeUpdate}
  onEdgeUpdateStart={onEdgeUpdateStart}
  onEdgeUpdateEnd={onEdgeUpdateEnd}
/>
```

**新 API**

```js
<ReactFlow
  onReconnect={onReconnect}
  onReconnectStart={onReconnectStart}
  onReconnectEnd={onReconnectEnd}
/>
```

### 6. 將 <code>parentNode</code> 重新命名為 <code>parentId</code>

如果你正在使用子流程，需要將 `node.parentNode` 重新命名為 `node.parentId`。`parentNode` 屬性有點誤導，因為它不是對父節點的引用，而是父節點的 `id`。

**舊 API**

```js
const nodes = [
  // some nodes ...
  {
    id: 'xyz-id',
    position: { x: 0, y: 0 },
    type: 'default',
    data: {},
    parentNode: 'abc-id',
  },
];
```

**新 API**

```js
const nodes = [
  // some nodes ...
  {
    id: 'xyz-id',
    position: { x: 0, y: 0 },
    type: 'default',
    data: {},
    parentId: 'abc-id',
  },
];
```

### 7. 自訂節點 props

我們將 `xPos` 和 `yPos` props 重新命名為 `positionAbsoluteX` 和 `positionAbsoluteY`

**舊 API**

```js
function CustomNode({ xPos, yPos }) {
  ...
}
```

**新 API**

```js
function CustomNode({ positionAbsoluteX, positionAbsoluteY }) {
  ...
}
```

### 8. 控制點元件類別名稱

我們重新命名了一些用於定義控制點當前狀態的類別。

- `react-flow__handle-connecting` 重新命名為 `connectingto` / `connectingfrom`
- `react-flow__handle-valid` 重新命名為 `valid`

### 9. <code>getNodesBounds</code> 選項

第二個參數的類型從 `nodeOrigin` 變更為 `options.nodeOrigin`

**舊 API**

```js
const bounds = getNodesBounds(nodes: Node[], nodeOrigin)
```

**新 API**

```js
const bounds = getNodesBounds(nodes: Node[], { nodeOrigin })
```

### 10. 定義節點和連線的 Typescript 變更

我們簡化了類型並修復了使用者可以傳遞 NodeData 泛型的函式問題。新方法是使用所有節點的聯集來定義你自己的節點類型。透過這項變更，你現在可以擁有多個具有不同資料結構的節點類型，並且始終可以透過檢查 `node.type` 屬性來區分它們。

**新 API**

```js
type NumberNode = Node<{ value: number }, 'number'>;
type TextNode = Node<{ text: string }, 'text'>;
type AppNode = NumberNode | TextNode;
```

You can then use the `AppNode` type as the following:

```js
const nodes: AppNode[] = [
  { id: '1', type: 'number', data: { value: 1 }, position: { x: 100, y: 100 } },
  { id: '2', type: 'text', data: { text: 'Hello' }, position: { x: 200, y: 200 } },
];
```

```js
const onNodesChange: onNodesChange<AppNode> = useCallback((changes) => setNodes(nds => applyChanges(changes, nds)), []);
```

你可以在 [Typescript 指南](/learn/advanced-use/typescript)中閱讀更多相關資訊。

### 11. 重新命名 <code>nodeInternals</code>

如果你正在使用 `nodeInternals`，需要將其重新命名為 `nodeLookup`。

**舊 API**

```js
const node = useStore((s) => s.nodeInternals.get(id));
```

**新 API**

```js
const node = useStore((s) => s.nodeLookup.get(id));
```

### 12. 移除已棄用的函式

我們移除了以下已棄用的函式：

- `getTransformForBounds`（由 `getViewportForBounds` 取代）
- `getRectOfNodes`（由 `getNodesBounds` 取代）
- `project`（由 `screenToFlowPosition` 取代）
- `getMarkerEndId`
- `updateEdge`（由 `reconnectEdge` 取代）

### 13. 自訂 <code>applyNodeChanges</code> 和 <code>applyEdgeChanges</code>

如果你編寫了自己的函式來應用變更，需要處理新的 "replace" 事件。我們移除了 "reset" 事件，並新增了 "replace" 事件來取代特定的節點或連線。

## 新功能

現在你已成功遷移到 v12，可以使用所有精彩的功能了。如上所述，v12 的最大更新包括：

### 1. 伺服器端渲染

你可以為節點定義 `width`、`height` 和 `handles`。這使得在伺服器上渲染流程並在客戶端進行水合成為可能：[伺服器端渲染指南](/learn/advanced-use/ssr-ssg-configuration)。

- **詳細資訊：** 在 v11 中，一旦節點被測量，`width` 和 `height` 就會由函式庫設定。這仍然會發生，但我們現在使用 `measured.width` 和 `measured.height` 來儲存這些資訊。在之前的版本中，`width` 和 `height` 總是讓人感到困惑。很難理解你不能使用它來傳遞實際的寬度或高度。函式庫新增這些屬性也不太明顯。我們認為新的實作解決了這兩個問題：`width` 和 `height` 是可選屬性，可用於定義尺寸，而函式庫設定的所有內容都儲存在 `measured` 中。

### 2. 計算流程

新的 hooks [`useHandleConnections`](/api-reference/hooks/use-handle-connections) 和 [`useNodesData`](/api-reference/hooks/use-nodes-data)，以及新的 [`updateNode`](/api-reference/hooks/use-react-flow#update-node) 和 [`updateNodeData`](/api-reference/hooks/use-react-flow#update-node-data) 函式（兩者都是 `useReactFlow` 的一部分）可用於管理節點之間的資料流：[計算流程指南](/learn/advanced-use/computing-flows)。我們也為連線新增了這些輔助函式（`updateEdge` 和 `updateEdgeData`）！

- **詳細資訊：** 使用一個節點的資料依賴於另一個節點的流程非常常見。你更新節點 A，並希望在連接的節點 B 中對這些變更做出反應。到目前為止，每個人都必須想出自訂解決方案。透過這個版本，我們想要改變這一點，並為你提供高效能的輔助函式來處理這樣的使用案例。

### 3. 深色模式和 CSS 變數

React Flow 現在內建深色模式，可以使用新的 [`colorMode`](/api-reference/react-flow#color-mode) prop（"light"、"dark" 或 "system"）來切換：[深色模式範例](/examples/styling/dark-mode)

- **詳細資訊：** 透過這個版本，我們想要讓在深色和淺色模式之間切換變得更容易，並為深色流程提供更好的起點。如果你傳遞 `colorMode="dark"`，我們會將類別名稱 "dark" 新增到包裝器並使用它來調整樣式。為了讓這個新功能的實作在我們這邊更容易，我們將大多數樣式切換到 CSS 變數。這些變數也可以在使用者端用於自訂流程。

### 4. 使用 TSDoc 提供更好的 DX

我們開始使用 TSDoc 以提供更好的 DX。在開發時，你的 IDE 現在會顯示 props 和 hooks 的文件。這對我們來說是一大步，使函式庫更易於存取和使用。我們還將在不久的將來使用 TSDoc 來產生文件。

### 更多功能和更新

還有更多！除了新的主要功能外，我們還新增了一些長期以來一直在我們清單上的小功能：

- **[`useConnection` hook](/api-reference/hooks/use-connection)：** 使用此 hook，你可以存取正在進行的連接。例如，你可以使用它根據當前的開始/結束控制點來為控制點著色或設定自訂連接線的樣式。
- **受控 `viewport`：** 這是一個進階功能。可能的使用案例包括為視口新增動畫或針對低解析度螢幕四捨五入轉換等。此功能帶來兩個新的 props：[`viewport`](/api-reference/react-flow#viewport) 和 [`onViewportChange`](/api-reference/react-flow#on-viewport-change)。
- **[`ViewportPortal`](/api-reference/components/viewport-portal) 元件：** 這使得可以在視口中渲染元素，而無需實作自訂節點。
- **[`onDelete`](/api-reference/react-flow#on-delete) 處理程序**：我們新增了 `onDeleteNodes` 和 `onDeleteEdges` 的組合處理程序，使對刪除操作做出反應變得更容易。
- **[`onBeforeDelete`](/api-reference/react-flow#on-before-delete) 處理程序**：使用此處理程序，你可以阻止/管理刪除操作。
- **[`isValidConnection`](/api-reference/react-flow#is-valid-connection) prop：** 這使得可以為所有連接實作一個驗證函式。它也會在以程式方式新增連線時被呼叫。
- **[`autoPanSpeed`](/api-reference/react-flow#autoPanSpeed) prop：** 用於控制自動平移時的速度。
- **[`paneClickDistance`](/api-reference/react-flow#paneClickDistance) prop：** mousedown/up 之間會觸發點擊的最大距離。
- **Background 元件**：新增 [`patternClassName`](/api-reference/components/background#pattern-class-name) prop，以便能夠使用類別名稱來設定背景圖案的樣式。例如，如果你想使用 Tailwind 設定背景圖案的樣式，這會很有用。
- **`onMove` 回呼**會在函式庫呼叫的視口更新（如 fitView 或 zoom-in）時觸發
- **`deleteElements`** 現在回傳已刪除的節點和已刪除的連線
- 為節點新增 **`origin` 屬性**
- 為連線新增 **`selectable` 屬性**
- **Node Resizer 更新**：調整群組大小時，子節點不會移動，範圍和展開會被正確識別
- 修正 `BezierEdge`、`StepEdge`、`SmoothStepEdge` 和 `StraightEdge` 元件的類型
- 函式庫建立的新連線僅在設定這些屬性時才具有 `sourceHandle` 和 `targetHandle` 屬性。（我們過去會傳遞 `sourceHandle: null` 和 `targetHandle: null`）
- 連線在 z-index 變更時不會掛載/卸載
- 連接線知道目標控制點的位置，因此路徑會正確繪製
- `nodeDragThreshold` 預設為 1 而不是 0
- 更好的選擇框可用性（在拖曳出流程時捕獲）
- 將 `selectable`、`deletable`、`draggable` 和 `parentId` 新增到 `NodeProps`
- 在未載入樣式時新增警告

### 內部變更

這些變更並不真正面向使用者，但對於使用內部 React Flow store 的人來說可能很重要：

- 最大的內部變更是我們建立了一個新套件 **@xyflow/system，其中包含與框架無關的輔助函式**，可供 React Flow 和 Svelte Flow 使用
  - **XYDrag** 用於處理拖曳節點和選擇
  - **XYPanZoom** 用於控制視口平移和縮放
  - **XYHandle** 用於管理新連接
- 我們將 `nodeInternals` 重新命名為 `nodeLookup`。該映射用作查找，但我們不會在任何變更時建立新的映射物件，因此它實際上僅用作查找。
- 我們移除了內部的 "reset" 事件，並新增了 "replace" 事件以能夠更新特定節點。
- 我們從 store 中移除了 `connectionNodeId`、`connectionHandleId`、`connectionHandleType`，並新增了 `connection.fromHandle.nodeId`、`connection.fromHandle.id`...
- 為連線新增 `data-id`
- 當使用者拖曳選擇時，`onNodeDragStart`、`onNodeDrag` 和 `onNodeDragStop` 也會被呼叫（除了 `onSelectionDragStart`、`onSelectionDrag`、`onSelectionDragStop`）
