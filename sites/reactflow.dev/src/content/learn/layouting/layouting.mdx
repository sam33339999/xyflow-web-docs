# 概述

我們經常被問到如何在 React Flow 中處理版面配置。我們尚未實作自己的版面配置解決方案，但會在本頁介紹一些可行的外部函式庫。我們將內容分為節點版面配置資源和連線路由資源兩部分。

你可以在我們的[遊樂場](https://play.reactflow.dev/)測試一些版面配置選項，或查看我們整理的[範例](/examples#layout)。

首先，讓我們建立一個簡單的範例流程，作為測試不同版面配置選項的基礎。

<RemoteCodeViewer route="learn/layouting-flow-1-empty" framework="react" />

接下來的每個範例都將基於這個空白流程建立。在可能的情況下，我們盡量將範例限制在一個 `index.js` 檔案中，方便你比較它們的設定方式。

## 節點版面配置

對於節點版面配置，有幾個值得關注的第三方函式庫：

| 函式庫                                            | 動態節點尺寸 | 子流程版面配置 | 連線路由 | 套件大小                                                                                                                                   |
| -------------------------------------------------- | ------------------ | ------------------ | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| [Dagre](https://github.com/dagrejs/dagre)          | 是                | 是¹               | 否           | <a href="https://pkg-size.dev/@dagrejs/dagre"><img src="https://pkg-size.dev/badge/bundle/39882" title="Bundle size for @dagrejs/dagre"/></a> |
| [D3-Hierarchy](https://github.com/d3/d3-hierarchy) | 否                 | 否                 | 否           | <a href="https://pkg-size.dev/d3-hierarchy"><img src="https://pkg-size.dev/badge/bundle/14697" title="Bundle size for d3-hierarchy"/></a>     |
| [D3-Force](https://github.com/d3/d3-force)         | 是                | 否                 | 否           | <a href="https://pkg-size.dev/d3-force"><img src="https://pkg-size.dev/badge/bundle/15623" title="Bundle size for d3-force"/></a>             |
| [ELK](https://github.com/kieler/elkjs)             | 是                | 是                | 是          | <a href="https://pkg-size.dev/elkjs"><img src="https://pkg-size.dev/badge/bundle/1455420" title="Bundle size for elkjs"/></a>                 |

¹ Dagre 目前有一個[未解決的問題](https://github.com/dagrejs/dagre/issues/238)，如果子流程中的任何節點連接到子流程外部的節點，會導致子流程的版面配置不正確。

我們大致按照從簡單到複雜的順序排列這些選項，其中 dagre 基本上是即插即用的解決方案，而 elkjs 則是功能完整、高度可配置的版面配置引擎。接下來，我們將簡要介紹如何在 React Flow 中使用這些函式庫。對於 dagre 和 elkjs，我們有一些單獨的範例可供參考：[這裡](/examples/layout/dagre)和[這裡](/examples/layout/elkjs)。

### Dagre

- 儲存庫：https://github.com/dagrejs/dagre
- 文件：https://github.com/dagrejs/dagre/wiki#configuring-the-layout

Dagre 是一個簡單的有向圖版面配置函式庫。它的配置選項很少，專注於速度而非選擇最佳版面配置。如果你需要將流程組織成樹狀結構，_我們強烈推薦使用 dagre_。

<RemoteCodeViewer route="learn/layouting-flow-2-dagre" framework="react" />

不費吹灰之力，我們就得到了一個組織良好的樹狀版面配置！每當呼叫 `getLayoutedElements` 時，我們會重置 dagre 圖形，並根據 `direction` 屬性設定圖形的方向（從左到右或從上到下）。Dagre 需要知道每個節點的尺寸才能進行版面配置，因此我們會遍歷節點列表並將它們加入到 dagre 的內部圖形中。

版面配置完成後，我們會回傳一個包含已配置節點和連線的物件。我們透過遍歷原始節點列表並根據儲存在 dagre 圖形中的節點來更新每個節點的位置。

dagre 的配置選項文件可以在[這裡](https://github.com/dagrejs/dagre/wiki#configuring-the-layout)找到，包括設定間距和對齊的屬性。

### D3-Hierarchy

- 儲存庫：https://github.com/d3/d3-hierarchy
- 文件：https://d3js.org/d3-hierarchy

當你知道你的圖形是具有單一根節點的樹狀結構時，d3-hierarchy 可以提供幾個有趣的版面配置選項。雖然該函式庫可以很好地配置簡單的樹狀結構，但它也提供了樹狀圖、分割版面配置和封閉圖的版面配置演算法。

<RemoteCodeViewer route="learn/layouting-flow-3-d3-hierarchy" framework="react" />

<Callout>
  D3-hierarchy 期望你的圖形具有單一根節點，因此不適用於所有情況。同時需要注意的是，d3-hierarchy 在計算版面配置時會為_所有_節點分配相同的寬度和高度，因此如果你要顯示許多不同類型的節點，它不是最佳選擇。
</Callout>

### D3-Force

- 儲存庫：https://github.com/d3/d3-force
- 文件：https://d3js.org/d3-force

如果想要比樹狀結構更有趣的東西，力導向版面配置可能是一個不錯的選擇。D3-Force 是一個基於物理的版面配置函式庫，可以透過對節點施加不同的力來定位它們。

因此，與 dagre 和 d3-hierarchy 相比，它的配置和使用稍微複雜一些。重要的是，d3-force 的版面配置演算法是迭代式的，因此我們需要一種方法在多次渲染中持續計算版面配置。

首先，讓我們看看它的效果：

<RemoteCodeViewer route="learn/layouting-flow-4-d3-force" framework="react" />

我們將 `getLayoutedElements` 改為一個名為 `useLayoutedElements` 的 hook。此外，我們不再明確傳入節點和連線，而是使用 `useReactFlow` hook 中的 `getNodes` 和 `getEdges` 函式。這在與 `initialized` 中的 store 選擇器結合使用時很重要，因為它可以防止我們在節點更新時重新配置模擬。

模擬配置了多個不同的力，你可以看到它們如何相互作用：在你自己的程式碼中試試看，以了解如何配置這些力。你可以在[這裡](https://d3js.org/d3-force)找到 d3-force 的文件和一些不同的範例。

<Callout>
  <strong>矩形碰撞</strong>
  D3-Force 有內建的碰撞力，但它假設節點是圓形的。我們在 `collision.js` 中組合了一個自訂力，使用類似的演算法但考慮了我們的矩形節點。歡迎使用它，如果你有任何改進建議，請告訴我們！
</Callout>

tick 函式會將模擬推進一步，然後使用新的節點位置更新 React Flow。我們還演示了如何在模擬執行時處理節點拖曳：如果你的流程不需要互動，可以忽略這部分！

<Callout>
  對於較大的圖形，每次渲染都永久計算力導向版面配置會帶來很大的效能影響。在這個範例中，我們有一個簡單的開關來開啟和關閉版面配置，但你可能想要想出其他方法，只在必要時計算版面配置。
</Callout>

### Elkjs

- 儲存庫：https://github.com/kieler/elkjs
- 文件：https://eclipse.dev/elk/reference.html （祝你好運！）

Elkjs 無疑是最可配置的選項，但也是最複雜的。Elkjs 是一個移植到 JavaScript 的 Java 函式庫，它提供了大量配置圖形版面配置的選項。

<RemoteCodeViewer route="learn/layouting-flow-6-elkjs" framework="react" />

在最基本的情況下，我們可以計算類似 dagre 的版面配置，但由於版面配置演算法是非同步執行的，我們需要建立一個類似於為 d3-force 建立的 `useLayoutedElements` hook。

<Callout>
  <strong>ELK 參考文件是你的新好朋友</strong>
  我們不常推薦 elkjs，因為它的複雜性讓我們在需要時難以支援使用者。如果你決定使用它，你會想要隨時準備好原始的 [Java API 參考文件](https://eclipse.dev/elk/reference.html)。
</Callout>

我們還包含了一些其他可用版面配置演算法的範例，包括非互動式的力導向版面配置。

### 值得一提的函式庫

當然，我們無法介紹所有版面配置函式庫：那樣我們就永遠不會做其他事情了！以下是我們遇到的一些其他值得關注的函式庫：

- 如果你想使用 dagre 或 d3-hierarchy，但需要支援不同尺寸的節點，[d3-flextree](https://github.com/klortho/d3-flextree) 和 [entitree-flex](https://github.com/codeledge/entitree-flex) 都很有前景。

  你可以在[這裡](/examples/layout/entitree-flex)找到如何在 React Flow 中使用 entitree-flex 的範例。

- [Cola.js](https://github.com/tgdwyer/WebCola) 看起來是一個很有前景的「基於約束」版面配置選項。我們還沒有時間深入研究它，但看起來你可以獲得類似 d3-force 的結果，但有更多的控制。

## 連線路由

如果你對連線路由沒有任何要求，可以使用上述任一版面配置函式庫來定位節點，讓連線自然分佈。否則，你需要研究一些連線路由的函式庫和技術。

這方面的選項比節點版面配置更有限，但以下是我們認為很有前景的一些資源：

- [react-flow-smart-edge](https://github.com/tisoap/react-flow-smart-edge)
- [Routing Orthogonal Diagram Connectors in JavaScript](https://medium.com/swlh/routing-orthogonal-diagram-connectors-in-javascript-191dc2c5ff70)

如果你探索了一些自訂連線路由選項，請考慮透過撰寫部落格文章或建立函式庫來回饋社群！

我們的[可編輯連線 Pro 範例](/examples/edges/editable-edge)也可以作為實作可沿特定路徑路由的自訂連線的起點。
