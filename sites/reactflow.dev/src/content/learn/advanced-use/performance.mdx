# 效能

在處理大量節點或複雜元件時，管理效能可能會很具挑戰性。以下是幾個有效的策略來優化 React Flow 的效能。

## 使用記憶化

React Flow 中效能問題的主要原因之一是不必要的重新渲染。由於節點移動會觸發頻繁的狀態更新，這可能導致效能瓶頸，特別是在較大的圖表中。

### 記憶化元件

作為屬性傳遞給 `<ReactFlow>` 元件的元件，包括自訂節點和連線元件，應該使用 `React.memo` 進行記憶化，或在父元件外部宣告。這確保 React 不會在每次渲染時為元件建立新的參考，否則會觸發不必要的重新渲染。

```tsx
const NodeComponent = memo(() => {
  return <div>{data.label}</div>;
});
```

### 記憶化函式

同樣地，作為屬性傳遞給 `<ReactFlow>` 的函式應該使用 `useCallback` 進行記憶化。這可以防止 React 在每次渲染時建立新的函式參考，否則也會觸發不必要的重新渲染。此外，像 `defaultEdgeOptions` 或 `snapGrid` 這樣的陣列和物件應該使用 `useMemo` 進行記憶化，以防止不必要的重新渲染。

```tsx
import React, { useCallback } from 'react';

const MyDiagram = () => {
  const onNodeClick = useCallback((event, node) => {
    console.log('Node clicked:', node);
  }, []);

  return <ReactFlow onNodeClick={onNodeClick} />;
};

export default MyDiagram;
```

## 避免在元件中存取節點

React Flow 中最常見的效能陷阱之一是在元件中直接存取 `nodes` 或 `edges`，或者存取視窗。這些物件在拖曳、平移或縮放等操作期間會頻繁變更，這可能導致依賴它們的元件發生不必要的重新渲染。

例如，如果你從儲存區中取得整個 `nodes` 陣列並過濾它以顯示選中的節點 ID，這種方法可能導致效能下降。每次更新 `nodes` 陣列都會觸發所有依賴元件的重新渲染，即使變更與選中的節點無關。

### 低效率範例

```tsx
const SelectedNodeIds = () => {
  // ❌ This will cause unnecessary re-renders!

  const nodes = useStore((state) => state.nodes);

  const selectedNodeIds = nodes.filter((node) => node.selected).map((node) => node.id);

  return (
    <div>
      {selectedNodeIds.map((id) => (
        <div key={id}>{id}</div>
      ))}
    </div>
  );
};
```

在此範例中，每次更新 `nodes` 陣列都會導致 `SelectedNodeIds` 元件重新渲染，即使選擇狀態沒有改變。

### 優化解決方案

為了避免不必要的重新渲染，將選中的節點儲存在狀態中的獨立欄位（使用 Zustand、Redux 或任何其他狀態管理解決方案）。這確保元件僅在選擇狀態改變時才重新渲染。

```tsx
const SelectedNodeIds = () => {
  const selectedNodeIds = useStore((state) => state.selectedNodeIds);

  return (
    <div>
      {selectedNodeIds.map((id) => (
        <div key={id}>{id}</div>
      ))}
    </div>
  );
};
```

透過將選中的節點與 `nodes` 陣列分離，你可以防止不必要的更新並提升效能。更多資訊請參閱我們的[狀態管理指南](/learn/advanced-use/state-management)。

## 摺疊大型節點樹

如果你的節點樹層級很深，一次渲染所有節點可能效率不佳。相反地，只顯示有限數量的節點，並允許使用者根據需要展開它們。你可以透過動態修改節點的 `hidden` 屬性來切換可見性。

```tsx
const handleNodeClick = (targetNode) => {
  if (targetNode.data.children) {
    setNodes((prevNodes) =>
      prevNodes.map((node) =>
        targetNode.data.children.includes(node.id)
          ? { ...node, hidden: !node.hidden }
          : node,
      ),
    );
  }
};
```

透過最初隱藏節點並僅在展開時渲染它們，我們可以在保持可用性的同時優化效能。

## 簡化節點和連線樣式

如果你已經在其他方面優化了效能，但在大量節點時仍然遇到效能問題，複雜的 CSS 樣式，特別是那些涉及動畫、陰影或漸層的樣式，可能會顯著影響效能。在這些情況下，請考慮減少節點樣式的複雜性。
