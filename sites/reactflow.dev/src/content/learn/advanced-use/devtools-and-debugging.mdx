# 開發者工具和除錯

<Callout type="info">
  這是一個正在進行的實驗，目標是實作我們自己的 React Flow 開發者工具。在我們開發實際套件的同時，我們很樂意在
  [Discord](https://discord.gg/Bqt6xrs) 上或透過電子郵件 info@xyflow.com 聽取你的回饋和想法。

React Flow 經常看起來像一個神秘的黑盒子，但實際上，如果你知道從哪裡看，可以揭示很多關於其內部狀態的資訊。在本指南中，我們將向你展示三種不同的方式來揭示你的流程圖的內部狀態：

- 一個 `<ViewportLogger />` 元件，顯示視窗的當前位置和縮放級別。
- 一個 `<NodeInspector />` 元件，揭示每個節點的狀態。
- 一個 `<ChangeLogger />` 元件，包裝你的流程圖的 `onNodesChange` 處理器並記錄每個變更的分派。

雖然我們發現這些工具對於確保 React Flow 正常運作很有用，但隨著你的流程圖及其互動變得更加複雜，你可能也會發現它們對除錯應用程式很有用。

我們鼓勵你將此範例中的任何或所有元件複製到你自己的專案中，並根據需要進行修改：每個元件都是獨立運作的！

## Node Inspector

`<NodeInspector />` 元件使用我們的 [`useNodes`](/api-reference/hooks/use-nodes) hook 來存取流程圖中的所有節點。通常我們不鼓勵使用此 hook，因為它會在任何節點變更時觸發重新渲染，但這正是它在除錯時如此有用的原因！

`width` 和 `height` 屬性是在 React Flow 測量節點尺寸後由其新增到每個節點的。我們將這些尺寸以及其他資訊（如節點的 id 和 type）傳遞給自訂的 `<NodeInfo />` 元件。

我們使用 [`<ViewportPortal />`](/api-reference/components/viewport-portal) 元件來讓我們將檢查器渲染到 React Flow 的視窗中。這意味著當使用者平移和縮放時，它的內容將與流程圖的其餘部分一起定位和變換。

## Change Logger

任何源自 React Flow 本身的節點和連線變更都會透過 `onNodesChange` 和 `onEdgesChange` 回呼函式傳達給你。如果你使用的是受控流程圖（這意味著你自己管理節點和連線），你需要將這些變更應用到你的狀態以保持一切同步。

`<ChangeLogger />` 元件使用自訂函式包裝你提供的 `onNodesChange` 處理器，該函式會攔截並記錄每個變更的分派。我們可以透過使用 [`useStore`](/api-reference/hooks/use-store) 和 [`useStoreApi`](/api-reference/hooks/use-store-api) hooks 來存取儲存區，然後相應地更新 React Flow 的內部狀態。這兩個 hooks 讓你可以強大地存取 React Flow 的內部狀態和方法。

除了除錯之外，使用 `<ChangeLogger />` 可以是了解 React Flow 如何運作的好方法，並讓你思考可以在每個變更之上建構的不同功能。

你可以在 API 參考中找到 [`NodeChange`](/api-reference/types/node-change) 和 [`EdgeChange`](/api-reference/types/edge-change) 類型的文件。

## Viewport Logger

`<ViewportLogger />` 是最簡單的範例，展示了如果你知道從哪裡找，可以從 React Flow 的儲存區中提取什麼狀態。視窗的狀態在內部儲存在 `transform` 鍵下（這個名稱我們從 [d3-zoom](https://d3js.org/d3-zoom#zoomTransform) 繼承而來）。此元件提取 transform 的 `x`、`y` 和 `zoom` 元件，並將它們渲染到 [`<Panel />`](/api-reference/components/panel) 元件中。
