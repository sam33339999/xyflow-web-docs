# useStoreApi()

[Source on GitHub](https://github.com/xyflow/xyflow/blob/main/packages/react/src/hooks/useStore.ts)

在某些情況下，你可能需要直接存取 store。這個 hook 返回 store 物件，可以按需用來存取狀態或分派操作。

> [!NOTE]
>
> 這個 hook 只應在沒有其他方式可以存取內部狀態時使用。對於許多常見的使用情境，都有專門的 hook 可用，例如 [`useReactFlow`](/api-reference/hooks/use-react-flow)、[`useViewport`](/api-reference/hooks/use-viewport) 等。


```tsx
import { useState, useCallback } from 'react';
import { ReactFlow, useStoreApi } from '@xyflow/react';

const NodesLengthDisplay = () => {
  const [nodesLength, setNodesLength] = useState(0);
  const store = useStoreApi();

  const onClick = useCallback(() => {
    const { nodes } = store.getState();
    const length = nodes.length || 0;

    setNodesLength(length);
  }, [store]);

  return (
    <div>
      <p>The current number of nodes is: {nodesLength}</p>
      <button onClick={onClick}>Update node length.</button>
    </div>
  );
};

function Flow() {
  return (
    <ReactFlow nodes={nodes}>
      <NodesLengthLogger />
    </ReactFlow>
  );
}
```

這個範例_按需_計算流程中的節點數量。這與 [`useStore`](/api-reference/hooks/use-store) hook 的範例形成對比，後者會在節點數量變更時重新渲染元件。

選擇按需計算值或訂閱變更是一種平衡取捨。一方面，在事件處理器中放入太多繁重的計算可能會讓你的應用程式感覺遲緩或無回應。另一方面，急切地計算值可能會導致緩慢或不必要的重新渲染。

我們提供這個 hook 和 [`useStore`](/api-reference/hooks/use-store)，讓你可以選擇最適合你使用情境的方法。

## TypeScript

這個 hook 接受自訂節點和連線類型的泛型參數。查看我們 TypeScript 指南中的[此章節](/learn/advanced-use/typescript#nodetype-edgetype-unions)以獲取更多資訊。

```tsx
const store = useStoreApi<CustomNodeType, CustomEdgeType>();
```
