很長一段時間以來，我們的範例一直建立在 [Sandpack](https://sandpack.codesandbox.io) 之上。這對我們來說是一個強大的工具，可以在文檔中提供互動式範例，但也付出了代價。

## 問題

我們喜歡 Sandpack，但我們不斷遇到一些痛點，最終我們決定不能忽視它們。

- **我們的範例載入速度很慢。** Sandpack 是一個令人印象深刻的工具，但它也是一個沉重的工具。Sandpack 客戶端本身需要一點時間載入，然後如果範例包含依賴項，這些依賴項也需要獲取。對於一次性的範例頁面來說，這還不算太糟，但特別是對於較長的文檔頁面（如我們的指南或教學），這真的會扼殺動力。

- **Sandpack 沒有正確支援 Svelte**，當我們首次發布 Svelte Flow 時。最終我們開發了一個單獨的 SvelteKit 應用程式來託管我們的 Svelte 範例，並調整了我們的範例檢視器以在 Sandpack 範例和簡單的 iframe 嵌入之間切換。

- 最後，**開發新範例是一件痛苦的事。** 我們的 React 範例的原始碼位於範例檢視器元件深處的資料夾中，並且對某些檔案或格式有特殊處理，這使得編寫範例變得相當困難：對範例的每次更改都會觸發文檔的熱重載，這意味著要等待 Sandpack 一次又一次地重新載入和重新渲染範例。

最重要的是，我們有一個完全獨立的應用程式，用於為我們的[範例概覽頁面](/examples)生成螢幕截圖！

## 解決方案

我們對 Svelte 範例的工作方式非常滿意（感謝 Peter），並決定探索一個統一的解決方案，既適用於我們的 Svelte 範例，也適用於 React 範例。最後，我們得到了比 SvelteKit 應用程式更簡單的東西，完全不需要伺服器，而是從靜態網站提供所有內容。

我們在 monorepo 中建立了一個單一的 [example-apps](https://github.com/xyflow/web/tree/main/apps/example-apps) 應用程式，它使用 [vite](https://vitejs.dev) 在開發期間提供範例，並將它們建置為靜態檔案以用於生產。如果你好奇，可以在 [examples-apps.xyflow.com](examples-apps.xyflow.com) 找到我們所有範例的簡單目錄。

我們還讓編寫範例變得更容易。開發範例現在更像是開發獨立應用程式，我們整理了一個簡單的腳手架腳本來幫助我們快速建立新範例：

```md
腳手架腳本透過複製樣板來幫助你快速為 reactflow.dev 或 svelteflow.dev 組合一個新範例。所有參數都是_必需的_。

用法：

pnpm scaffold <FRAMEWORK> <ROUTE>

範例：

pnpm scaffold react blog/web-audio/demo

pnpm scaffold svelte guides/getting-started

參數：

FRAMEWORK 'react' | 'svelte'

              範例將使用的框架。這會影響生成的檔案與 ROUTE 參數結合後放置的位置。

ROUTE string

              範例應用程式與 FRAMEWORK 參數結合後將提供的路由片段。例如，將腳本呼叫為
              `pnpm scaffold react examples/nodes/custom-node` 將會建立範例腳手架並使其在
              '/react/examples/nodes/custom-node/index.html' 可存取。
```

## 有什麼缺點嗎？

在過渡過程中，我們失去了一個重要功能：直接在文檔網站上編輯範例的能力。對於某些使用者來說，這可能是一件大事，但為了補償，我們現在除了 CodeSandbox 之外，還支援在 StackBlitz 中開啟範例！
