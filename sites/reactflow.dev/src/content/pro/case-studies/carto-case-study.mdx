import QandA from '@/components/case-study-qa';

<QandA
  className="mt-16"
  question="可以簡單介紹一下 Carto 嗎？"
  answer="CARTO 是一個位置智慧平台。我們的客戶可以透過我們的資料目錄和分析工具來解決他們的空間問題。他們在我們的完全雲端原生平台上完成這些工作，因為我們與最現代和強大的雲端資料倉儲整合（Google BigQuery、Snowflake、Amazon Redshift 等）。"
/>

<QandA
  question="你在 Carto 的角色是什麼？"
  answer="作為前端開發者，我努力為我們的平台打造最佳的 UI 和 UX。因此，我們的團隊目前使用 React 生態系統的技術堆疊，包括為終端使用者開發的應用程式（Workflows、Builder、Workspace）以及為開發者提供的一套工具（CARTO for React、CARTO for deck.gl）。"
/>

<QandA
  question="你面臨什麼問題或決策讓你決定使用 React Flow？"
  answer="我們想為終端使用者提供易於使用且直觀的 UI，讓他們可以使用空間資料來建立、分享和執行分析流程。傳統上這只有少數專家能做到，他們對 Spatial SQL 領域有豐富的知識，並使用難以使用的環境（複雜的桌面工具、CLI 等）。"
/>

<QandA
  question="你目前如何使用 React Flow？"
  answer="我們使用 React Flow 作為我們的「Workflows」，這是我們的主要視覺化工具，透過無程式碼工作流程方法來自動化資料準備和分析管線。它與我們的 Workspace 和 Builder 工具整合（用於資產管理和地圖建立）。"
/>

<QandA
  question="你能舉例說明 React Flow 中你發現特別有用的東西嗎？"
  answer="我們評估了幾個工具（甚至用不同的函式庫開始了一個概念驗證），但在對 React Flow 進行詳細分析後，我們很快就遷移了，因為它設計良好的 API、使用 hook 的現代 React 程式碼、可擴展性和良好的文檔。此外，我們發現 Pro 範例非常有用，可以輕鬆增強功能。"
/>

<QandA
  question="到目前為止，React Flow 訂閱的功能如何幫助你？"
  answer="我會說所有功能都有幫助。我們總是渴望改善 Workflows 的 UI/UX，例如我們在 Minimaps 推出後就立即包含了它。我們還使用了「Undo and Redo」Pro 範例來啟發我們的實作，最近我們回報了一個關於節點上鍵盤事件的小但煩人的問題，它很快就得到處理並包含在補丁版本中。"
/>

<QandA
  question="在使用函式庫的過程中你遇到任何困難嗎？"
  answer="從一開始整合到我們的前端程式碼庫就非常順利。我們能夠非常自主地進行整合"
/>
