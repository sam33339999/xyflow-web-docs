<QandA
  className="mt-16"
  question="可以用一兩句話介紹 OneSignal 嗎？"
  answer="OneSignal 是一個客戶互動平台。我們為行動推播通知、網頁推播、電子郵件、應用程式內訊息和 SMS 提供訊息解決方案。我們每天傳送超過 120 億則訊息，現在每 5 個新應用程式中就有 1 個使用我們的 SDK。"
/>

<QandA
  question="你面臨什麼問題或決策讓你決定使用我們的函式庫？"
  answer="我們的客戶使用 OneSignal 透過訊息來管理他們使用者的旅程，包括入門活動、重新互動活動、一次性促銷等。幾年前，當我們開始考慮提供更強大的工具來建立和管理這些訊息序列時，我們開始研究開源函式庫，同時也考慮自己建立。在發現 React Flow 並建立早期概念驗證後，我們毫無疑問地選擇使用它而不是從頭開始建立。"
/>

<QandA
  question="你目前如何使用 React Flow？"
  answer="該功能演變成 OneSignal Journeys，一個易於使用的視覺化工作流程建構器，用於自動化你的訊息並引導你的使用者。它使我們的客戶能夠使用推播、電子郵件、應用程式內、SMS、webhook 來排序活動，以及新增等待期間、排程、決策樹和 A/B 分割分支等關鍵動作。"
/>
<QandA
  question="你能舉例說明 React Flow 中你發現特別有用的東西嗎？"
  answer="React Flow 文檔非常棒。我們非常感謝他們對細節的關注、範例和 CodeSandbox 整合。我們在易用性和使用者體驗上投入了大量時間，開箱即用的 React Flow 就具備所有這些，但也非常容易設定樣式和自訂以符合我們的視覺風格和設計系統，這對我們來說很重要。"
/>
<QandA
  question="在使用函式庫時你遇到任何問題或挑戰嗎？如果有，它們是如何解決的？"
  answer="任何出現的問題我們通常都可以透過參考文檔來解決。文檔非常棒。GitHub issue 和社群也非常活躍，我很感激，所以通常在 GitHub 中快速搜尋就能找到我們要找的東西。"
/>
<QandA
  question="到目前為止，React Flow Pro 的功能如何幫助你？"
  answer="我們大約 2 年前開始使用 React Flow，我相信那是在今天存在的許多 Pro 功能之前。如果我們今天從頭開始，這些功能會很棒。然而，我們當時最終編寫了一些自己的解決方法。例如，我記得我們早期在自動布局或處理隱藏節點方面遇到了問題。"
/>
