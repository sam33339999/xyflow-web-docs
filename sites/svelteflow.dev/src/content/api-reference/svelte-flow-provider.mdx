# \<SvelteFlowProvider />

[在 GitHub 上查看原始碼](https://github.com/xyflow/xyflow/blob/main/packages/svelte/src/lib/components/SvelteFlowProvider/SvelteFlowProvider.svelte)

`<SvelteFlowProvider />` 元件使用 Svelte context 包裹其子節點，使得在 [`<SvelteFlow />`](/api-reference/svelte-flow) 元件之外也能存取流程的內部狀態。我們提供的許多 hooks 都依賴此元件才能運作。

```svelte filename="App.svelte"
<script>
  import { SvelteFlow, SvelteFlowProvider } from '@xyflow/svelte';
  import '@xyflow/svelte/dist/style.css';

  import Sidebar from './Sidebar.svelte';

  /* ... */
</script>

<SvelteFlowProvider>
  <SvelteFlow bind:nodes bind:edges />
  <Sidebar />
</SvelteFlowProvider>
```

```svelte filename="Sidebar.svelte"
<script>
  import { SvelteFlow, SvelteFlowProvider } from '@xyflow/svelte'

  // 這個 hook 只有在使用它的元件是 <SvelteFlowProvider /> 的子元件時才能運作
  const nodes = useNodes()
</script>

<aside>
  {#each nodes.current as node (node.id)}
    <div key={node.id}>
      Node {node.id} -
        x: {node.position.x.toFixed(2)},
        y: {node.position.y.toFixed(2)}
    </div>
  {/each}
</aside>
```

<Callout type="info">
  `<SvelteFlowProvider />` 提供的狀態首先使用預設值初始化。只有在 `<SvelteFlow />` 元件初始化後，狀態才會被替換為正確的值。然而，你可以預期這會在第一次渲染之前發生。
</Callout>

## 注意事項

- 如果你使用路由器並希望流程的狀態在路由之間保持，那麼將 `<SvelteFlowProvider />` 元件放在路由器_之外_是至關重要的。
- 如果同一頁面上有多個流程，你需要使用單獨的 `<SvelteFlowProvider />`。
