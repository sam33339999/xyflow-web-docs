# 佈局

我們經常被問到如何在 Svelte Flow 中處理佈局。雖然我們可以在 Svelte Flow 中內建一些基本的佈局功能,但我們相信**你最了解應用程式的需求**,而且外面有這麼多選擇,我們認為最好由你選擇最合適的工具(更不用說這對我們來說會是一大堆工作)。

如果你不知道有哪些選擇,這並沒有太大幫助,所以本指南就是為了幫助你!我們將把事情分為節點佈局資源和邊路由資源。

首先,讓我們探索幾個不同的佈局函式庫,以及它們如何與 Svelte Flow 一起使用。

## 佈局節點

對於佈局節點,有幾個我們認為值得查看的第三方函式庫:

| 函式庫                                             | 動態節點大小 | 子流程佈局 | 邊路由 | 打包大小                                                                                                                                      |
| -------------------------------------------------- | ------------ | ---------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| [Dagre](https://github.com/dagrejs/dagre)          | 是           | 是¹        | 否     | <a href="https://pkg-size.dev/@dagrejs/dagre"><img src="https://pkg-size.dev/badge/bundle/39882" title="Bundle size for @dagrejs/dagre"/></a> |
| [D3-Hierarchy](https://github.com/d3/d3-hierarchy) | 否           | 否         | 否     | <a href="https://pkg-size.dev/d3-hierarchy"><img src="https://pkg-size.dev/badge/bundle/14697" title="Bundle size for d3-hierarchy"/></a>     |
| [D3-Force](https://github.com/d3/d3-force)         | 是           | 否         | 否     | <a href="https://pkg-size.dev/d3-force"><img src="https://pkg-size.dev/badge/bundle/15623" title="Bundle size for d3-force"/></a>             |
| [ELK](https://github.com/kieler/elkjs)             | 是           | 是         | 是     | <a href="https://pkg-size.dev/elkjs"><img src="https://pkg-size.dev/badge/bundle/1455420" title="Bundle size for elkjs"/></a>                 |

¹ Dagre 目前有一個[未解決的問題](https://github.com/dagrejs/dagre/issues/238),如果子流程中的任何節點連接到子流程外的節點,它將無法正確佈局子流程。

我們大致按照從最簡單到最複雜的順序排列這些選項,其中 dagre 主要是一個即插即用的解決方案,而 elkjs 是一個功能齊全、高度可配置的佈局引擎。下面,我們將簡要介紹這些函式庫如何與 Svelte Flow 一起使用的範例。特別是對於 dagre 和 elkjs,我們有一些單獨的範例,你可以參考[這裡](/examples/layout/dagre)和[這裡](/examples/layout/elkjs)。

### Dagre

- 儲存庫: https://github.com/dagrejs/dagre
- 文檔: https://github.com/dagrejs/dagre/wiki#configuring-the-layout

Dagre 是一個用於佈局有向圖的簡單函式庫。它的配置選項很少,專注於速度而不是選擇最優佈局。如果你需要將流程組織成樹狀結構,_我們強烈推薦 dagre_。

<RemoteCodeViewer route="guides/layouting/dagre" framework="svelte" />

不費吹灰之力,我們就得到了一個組織良好的樹狀佈局!每當調用 `getLayoutedElements` 時,我們將重置 dagre 圖形,並根據 `direction` 屬性設置圖形的方向(從左到右或從上到下)。Dagre 需要知道每個節點的尺寸才能佈局它們,所以我們遍歷節點列表並將它們添加到 dagre 的內部圖形中。

佈局圖形後,我們將返回一個包含佈局後節點和邊的物件。我們通過遍歷原始節點列表並根據 dagre 圖形中儲存的節點更新每個節點的位置來實現這一點。

dagre 的配置選項文檔可以在[這裡](https://github.com/dagrejs/dagre/wiki#configuring-the-layout)找到,包括設置間距和對齊的屬性。

### D3-Hierarchy

- 儲存庫: https://github.com/d3/d3-hierarchy
- 文檔: https://d3js.org/d3-hierarchy

當你知道你的圖形是具有單個根節點的樹時,d3-hierarchy 可以提供一些有趣的佈局選項。雖然該函式庫可以很好地佈局簡單的樹,但它也有樹狀圖、分區佈局和封閉圖的佈局演算法。

<RemoteCodeViewer route="guides/layouting/d3" framework="svelte" />

<Callout>
  D3-hierarchy 期望你的圖形具有單個根節點,所以它不會在所有情況下都有效。同樣重要的是要注意,d3-hierarchy 在計算佈局時為_所有_節點分配相同的寬度和高度,所以如果你顯示許多不同的節點類型,它不是最佳選擇。
</Callout>

### D3-Force

- 儲存庫: https://github.com/d3/d3-force
- 文檔: https://d3js.org/d3-force

對於比樹更有趣的東西,力導向佈局可能是一個不錯的選擇。D3-Force 是一個基於物理的佈局函式庫,可以通過對節點應用不同的力來定位它們。

因此,與 dagre 和 d3-hierarchy 相比,它的配置和使用稍微複雜一些。重要的是,d3-force 的佈局演算法是迭代的,所以我們需要一種方法在多次渲染中持續計算佈局。

首先,讓我們看看它做了什麼:

<RemoteCodeViewer route="guides/layouting/d3-force" framework="svelte" />

在我們的 Svelte 實作中,我們使用 Svelte 的生命週期鉤子和響應式狀態來管理力模擬。模擬配置了許多不同的力,所以你可以看到它們如何互動:在你自己的程式碼中嘗試,看看你想如何配置這些力。你可以在[這裡](https://d3js.org/d3-force)找到 d3-force 的文檔和一些不同的範例。

<Callout>
  <strong>矩形碰撞</strong>
  D3-Force 有一個內建的碰撞力,但它假設節點是圓形的。我們在 `collision.js` 中組合了一個自訂力,使用類似的演算法,但考慮了我們的矩形節點。隨意使用它,或者如果你有任何改進建議,請告訴我們!
</Callout>

tick 函式將模擬推進一步,然後使用新的節點位置更新 Svelte Flow。我們還包括了一個關於如何在模擬運行時處理節點拖動的演示:如果你的流程不是互動的,你可以忽略那部分!

<Callout>
  對於較大的圖形,永遠在每次渲染時計算力佈局會帶來很大的效能影響。在這個範例中,我們有一個簡單的切換來開啟和關閉佈局,但你可能想要想出一些其他方法,只在必要時計算佈局。
</Callout>

### Elkjs

- 儲存庫: https://github.com/kieler/elkjs
- 文檔: https://eclipse.dev/elk/reference.html (祝你好運!)

Elkjs 當然是最可配置的選項,但它也是最複雜的。Elkjs 是一個已經移植到 JavaScript 的 Java 函式庫,它提供了大量用於配置圖形佈局的選項。

<RemoteCodeViewer route="guides/layouting/elkjs" framework="svelte" />

在最基本的情況下,我們可以計算類似於 dagre 的佈局,但因為佈局演算法是非同步運行的,我們需要處理 promise 並相應地更新我們的 Svelte 狀態。

<Callout>
  <strong>ELK 參考是你的新好朋友</strong>
  我們不經常推薦 elkjs,因為它的複雜性使我們在需要時難以支援人們。如果你決定使用它,你會想要隨時查閱原始的 [Java API 參考](https://eclipse.dev/elk/reference.html)。
</Callout>

我們還包括了一些其他可用佈局演算法的範例,包括非互動式力佈局。

### 值得一提的

當然,我們無法介紹所有的佈局函式庫:我們永遠不會做其他事情!這裡有一些我們遇到的其他函式庫,可能值得一看:

- 如果你想使用 dagre 或 d3-hierarchy 但需要支援不同尺寸的節點,[d3-flextree](https://github.com/klortho/d3-flextree) 和 [entitree-flex](https://github.com/codeledge/entitree-flex) 看起來很有前途。

- [Cola.js](https://github.com/tgdwyer/WebCola) 看起來像是所謂「基於約束」佈局的一個有前途的選項。我們還沒有時間適當地研究它,但看起來你可以獲得類似於 d3-force 的結果,但有更多的控制。

## 路由邊

如果你對邊路由沒有任何要求,你可以使用上面的佈局函式庫之一來定位節點,讓邊隨意放置。否則,你會想要研究一些邊路由的函式庫和技術。

你在這裡的選擇比節點佈局更有限,但這裡有一些我們認為看起來有前途的資源:

- [Routing Orthogonal Diagram Connectors in JavaScript](https://medium.com/swlh/routing-orthogonal-diagram-connectors-in-javascript-191dc2c5ff70)

如果你確實探索了一些自訂邊路由選項,請考慮透過撰寫部落格文章或建立函式庫來回饋社群!

你可以使用 Svelte Flow 中的可編輯邊功能作為實作可以沿特定路徑路由的自訂邊的起點。
