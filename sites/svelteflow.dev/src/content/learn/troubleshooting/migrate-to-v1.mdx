# 遷移到 Svelte Flow 1.0

Svelte Flow 1.0 是使用 Svelte 5 從頭開始建構的,包含許多新功能和改進。本指南將幫助你從 Svelte Flow 0.x 遷移到 1.0。

<Callout type="info">
  如果你正在尋找 Svelte Flow 0.x 文檔,請參閱 [legacy.svelteflow.dev](https://legacy.svelteflow.dev)。
</Callout>

## 新功能

- **[重新連接邊](/examples/edges/reconnect-edge)**: 你可以使用新的 `<EdgeReconnectAnchor />` 元件重新連接邊。它可以用於在自訂邊上添加自訂重新連接點。
- **鍵盤導航和無障礙**: 我們添加了對鍵盤導航的支援,並改進了螢幕閱讀器的無障礙性。你現在可以使用 Tab 鍵瀏覽節點和邊,並使用方向鍵移動節點。可以通過 [**disableKeyboardA11y**](/api-reference/svelte-flow#disablekeyboarda11y) 停用
- **[點擊連接](/examples/edges/click-connect)**: 你現在可以通過逐一點擊控制點來建立新連接。
- **[增強的 ViewportPortal](/api-reference/components/viewport-portal)**: 你現在可以決定是否要在視窗中的節點和邊下方或上方渲染某些內容。
- **改進的 [fitView](/api-reference/hooks/use-svelte-flow#fitview)**: 我們微調了 `fitView` 函式,以更好地處理動態添加的節點。
- **colorModeSSR** 屬性: 當 colorMode 設置為 'system' 時,你可以為伺服器端渲染傳遞一個備用顏色模式。
- [**elevateNodesOnSelect**](/api-reference/svelte-flow#elevateNodesOnSelect) 和 [**elevateEdgesOnSelect**](/api-reference/svelte-flow#elevateEdgesOnSelect): 控制選中時節點和邊是否應該通過 z-index 提升。
- [**noDragClass、noWheelClass、noPanClass**](/api-reference/svelte-flow#style-props): 你現在可以修改用於停用拖動、平移和縮放的類別名稱。
- [**onselectionchange**](/api-reference/svelte-flow#onselectionchange) 和 [**useOnSelectionChange**](/api-reference/hooks/use-on-selection-change): 你現在可以通過回呼監聽選擇變更

## 重大變更

### `nodes` 和 `edges` 現在使用 `$state.raw` 而不是 `writable`

Svelte 5 引入了 runes,現在用於節點和邊。

**舊 API**

```js
const nodes = writable([...]);
const edges = writable([...]);
```

**新 API**

```js
let nodes = $state.raw([...]);
let edges = $state.raw([...]);
```

### 更新節點和邊

以前可以更新單個節點屬性。理論上,這在 `$state` 中也是可能的,但是這樣做的[效能影響](https://svelte.dev/playground/e6f804ba6da348bc8b6a0a13c59672cb?version=5.19.0)不幸太大,所以我們選擇使用 `$state.raw`。

這意味著從現在開始,`nodes` 和 `edges` 將被視為不可變的。如果你手動進行更新,請確保:

1. 更新屬性時建立一個新的 node/edge 物件。
2. 重新分配 nodes/edges 陣列(技術上以前也需要這樣做)

```js
nodes[0].position.x = 100; // 不會起作用

const newNode = { ...nodes[0] };
newNode.position.x = 100;
nodes[0] = newNode; // 不足以觸發更新
nodes = [...nodes]; // 這樣才會起作用

nodes = nodes.map((node) => {
  if (node.id === '1') {
    return { ...node, position: { ...node.position, x: 100 } };
  }
  return node;
}); // 也有效

updateNode('1', (node) => ({
  ...node,
  position: { ...node.position, x: 100 },
})); // 使用 useSvelteFlow 的 updateNode 輔助函式
```

### `nodes` 和 `edges` 需要從 `<SvelteFlow />` 綁定

**舊 API**

```js
<SvelteFlow {nodes} {edges} />
```

**新 API**

```js
<SvelteFlow bind:nodes bind:edges />
```

如果 `nodes` 和 `edges` 存在於單獨的模組中,你可以使用[函式綁定](https://svelte.dev/docs/svelte/bind#Function-bindings)。

```js
// store.svelte.js

let nodes = $state.raw([...]);
let edges = $state.raw([...]);

export const getNodes = () => nodes;
export const getEdges = () => edges;
export const setNodes = (newNodes) => nodes = newNodes;
export const setEdges = (newEdges) => edges = newEdges;
```

```js
// BaseComponent.svelte

<script>
  import { getNodes, getEdges, setNodes, setEdges } from 'store.svelte.js';
</script>

<SvelteFlow bind:nodes={getNodes, setNodes} bind:edges={getEdges, setEdges} />
```

### 自訂節點和邊屬性

這在很大程度上是 Svelte 5 中的一般變更,但它確實對自訂節點和邊的屬性定型產生了很大影響。

**舊 API**

```js
// CustomNode.svelte

type $$Props = NodeProps;

export let data: $$Props['data'];
export let position: $$Props['position'];
export let selected: $$Props['selected'];
```

**新 API**

```js
let { data, position, selected } : NodeProps = $props();
```

### 鉤子

鉤子現在返回響應式值而不是 writables。因為 `$state` 值不能[直接由函式返回](https://svelte.dev/docs/svelte/$state#Passing-state-into-functions),我們必須返回一個帶有 `.current` 屬性的物件以保持響應性。在這方面,我們[遵循官方趨勢](https://svelte.dev/docs/svelte/svelte-reactivity#MediaQuery),這是 Svelte 函式庫作者設定的。

**舊 API**

```js
const edges = useEdges();
$: console.log(edges);
```

**新 API**

```js
const edges = useEdges();
$inspect(edges.current);
```

請注意,在 `useNodes`、`useEdges` 和 `useViewport` 的情況下,對 `.current` 的重新分配有效!

```js
const nodes = useNodes();

function updateNodes() {
   nodes.current = [...]
}
```

### 綁定視窗

綁定視窗現在在 Svelte 5 中原生運作。你可以存取內部視窗或綁定你自己的視窗物件以供使用。

**舊 API**

```js
const viewport = writable<Viewport>({ x: 100, y: 100, zoom: 1.25 });

<SvelteFlow {viewport} />
```

**新 API**

```js
let viewport = $state < Viewport > { x: 100, y: 100, zoom: 1.25 };

<SvelteFlow bind:viewport />;
```

### 自訂連接線

以前可以通過將其傳遞給[插槽](https://svelte.dev/docs/svelte/legacy-slots)來使用自訂連接線。在 Svelte Flow 1.0 中,我們為此引入了一個名為 `connectionLineComponent` 的新屬性。

**舊 API**

```js
<SvelteFlow {nodes} {edges}>
  <ConnectionLine slot="connectionLine" />
  <Background variant={BackgroundVariant.Lines} />
</SvelteFlow>
```

**新 API**

```js
<SvelteFlow {nodes} {edges} connectionLineComponent={ConnectionLine}>
  <Background variant={BackgroundVariant.Lines} />
</SvelteFlow>
```

### `onEdgeCreate` 變成 `onbeforeconnect`

`onedgecreate` 在建立新邊之前被調用。現在稱為 `onbeforeconnect`,以更好地與 [`onbeforedelete`](/api-reference/svelte-flow#onbeforedelete) 等事件對齊。

**舊 API**

```js
<SvelteFlow
  {nodes}
  {edges}
  onEdgeCreate={(connection) => ({...connection, id: crypto.randomUUID()})}
/>
```

**新 API**

```js
<SvelteFlow
  bind:nodes
  bind:edges
  onbeforeconnect={(connection) => ({ ...connection, id: crypto.randomUUID() })}
/>
```

### `<EdgeLabelRenderer/>` 變成 [`<EdgeLabel />`](/api-reference/components/edge-label)

`EdgeLabelRenderer` 元件現在稱為 `EdgeLabel`。由於它一開始只是一個簡單的入口,將其命名為「渲染器」有點誤導。除此之外,新的 `EdgeLabel` 元件現在還自動處理標籤上的點擊,並知道它屬於哪個邊。

**舊 API**

```js filename="CustomEdge.svelte"
<BaseEdge id={id} path={path} />
<EdgeLabelRenderer>
  <div
    style:transform={`translate(${labelX}px, ${labelY}px)`}
  >
    My Edge Label
  </div>
</EdgeLabelRenderer>
```

**新 API**

```js filename="CustomEdge.svelte"
<BaseEdge path={path} />
<EdgeLabel x={labelX} y={labelY} selectEdgeOnClick>
  <div>My Edge Label</div>
</EdgeLabel>
```
