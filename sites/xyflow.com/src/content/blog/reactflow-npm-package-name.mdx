2019 年我們開始建立[一個用於建立基於節點的 UI 的函式庫](https://github.com/xyflow/xyflow)，並決定稱它為「React Flow」。這是一個好名字，所以當然「reactflow」和「react-flow」都已經被佔用了。我們能選擇的最佳選項是「react-flow-renderer」，所以我們接受了我們能得到的。

三年和許多 Github 星星之後，我們想要一個更簡潔的名稱。「reactflow」和「react-flow」都已經超過 6 年沒有使用或更改，所以我使用 `npm view reactflow _npmUser` 找到了與「reactflow」相關聯的電子郵件地址，發送了一封友好的電子郵件詢問我們是否可以使用它，然後祈禱。

僅僅 2 小時內，所有者就回覆了，說他已經將權利移交給我們（?!?!）。感謝一位快速回應的陌生人，比預期更快更容易，我們開始營業了 <Emoji content="🔥" />。我們即將發布一個新的主要版本，我們很興奮新的「reactflow」套件將隨著發布而來。

## 犯了錯誤

之前的所有者在 10 年前只發布了一個版本的套件。我想從一個名為「v11.0.0-beta」的全新套件開始，但我必須先取消發布那個舊版本。

那是唯一的版本，所以我必須使用「force」參數。但這應該不是問題，因為我可以發布新版本，對吧？

```sh
npm unpublish@0.1.0 —force
```

然後是時候製作我們的新名稱，並期待一個光明燦爛的未來。

```sh
npm publish
```

然後，一個可怕的錯誤訊息...

```sh
"Package name too similar to existing package react-flow"
```

但我們剛才還有這個名字？！這兩個名字在過去 6 年裡一直共存著？？發生了什麼事？

經過瘋狂的 google 搜尋，我發現 npm 在幾年前引入了一個[防範套件名稱誤植的安全功能](https://blog.npmjs.org/post/168978377570/new-package-moniker-rules)，遠在這兩個套件名稱創建之後，現在阻止我使用「reactflow」套件。我感覺很糟糕，不敢相信我失去了一個剛從一位善良陌生人那裡收到的套件！

## 拿回 reactflow

兩分鐘的哀傷和瘋狂 google 搜尋後，我意識到我真的搞砸了，並給 npm 發了一條訊息解釋我的情況。他們回答說他們對此無能為力，我們應該使用範疇套件名稱，或遵循套件名稱爭議政策 [https://www.npmjs.com/policies/disputes](https://www.npmjs.com/policies/disputes)。這很糟糕。

我們來來回回寫了一些郵件，最後在當天結束時，他們回滾了我犯的錯誤並恢復了之前的版本 0.1.0。鬆了一口氣！<Emoji content="🙏" />

感謝 npm 支援，所有想使用 React Flow 的人現在可以使用 `npm install reactflow` 而不是 `npm install react-flow-renderer`，這隨著我們的 [v11 更新](https://reactflow.dev/blog/react-flow-v11/)一起發布。感覺很好。<Emoji content="😌" />

## 如何避免犯同樣的錯誤

1. 如果你可能想再次使用這個名稱，永遠不要取消發布套件的最後一個版本。
2. 永遠不要在 npm 上做任何你不是 100% 確定的事情。
3. npm 支援很棒 ❤️
