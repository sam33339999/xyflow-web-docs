眾所周知，許多開源專案資金不足。我們認為其中一個原因是**開源社群在爭取應得資金方面做得不夠好**。透過明確告訴適當的組織我們為何以及如何希望他們在財務上支持我們的工作，開源專案可以獲得更公平的補償，並造就更健康的開源生態系統。

我們維護 [React Flow](https://github.com/xyflow/xyflow)，這是一個用於建立節點式使用者介面的開源函式庫。我們的故事發展與一些幸運的函式庫類似：

1. 建立一個函式庫來滿足你的需求並將其開源
2. 獲得有相同需求的使用者，他們開始提交問題和請求
3. 透過持續維護和開發函式庫來建立信任
4. 開啟你的 Github 贊助頁面

不幸的是，我們的 Github 贊助頁面無法支付開銷，甚至差得很遠。為了避免尋找接案工作或尋求投資，我們決定透過在網站上添加以下內容，以更直接的方式爭取資金：

我們開始以更快的速度獲得付費客戶，每位客戶支付的金額都超過任何贊助者，**而且我們在幾個月內就達到了「泡麵獲利」（能維持基本生活）。**

**是什麼造成了如此巨大的變化？**

**我們如何繞過困擾開源世界的問題？**

經過一些實驗和使用者研究，以下是我們對這些問題的答案：

## 薄殼開放核心模式

我們從捐款模式轉變為[薄殼開放核心](https://www.bcg.com/publications/2021/open-source-software-strategy-benefits)模式。這就是為什麼我們保持 React Flow 函式庫採用 MIT 授權，並在函式庫的「外殼」上添加少量功能（專業範例和一些技術支援）。透過在核心函式庫之上提供一些小東西，我們創造了點擊「購買」按鈕的理由。

起初，我們擔心訂閱者會對我們有更高的期望，因為他們現在要付費使用我們的工作。我們想像著快速回應時間、每月電子報、更頻繁的發布，以及必須不斷證明我們的價值。但事實並非如此。

從與訂閱者的交談中，我們了解到，在訂閱之後，他們不認為自己只是為訂閱中的附加功能付費，而是為整個函式庫付費（文件、指南、新功能，以及他們能夠更輕鬆地使用我們的函式庫建立的應用程式）。這是真的：他們不只是為附加功能付費，他們**確實**是在為整個函式庫付費。對他們來說，這是值得的。

## 認識轉換漏斗

每個收到資金的開源專案都有一個「購買漏斗」（一個人成為付費客戶所採取的步驟），即使只是一個「請我喝咖啡」按鈕。認識並修改這個漏斗的步驟，可以將目標非付費使用者（如大型公司）轉變為財務支持者。

我們在 React Flow 視窗的角落添加了一個小標記。它很容易移除，而且根據我們的 MIT 授權，這樣做完全合法。在可以移除此標記的程式碼中，我們連結到我們的定價網站，並請求如果他們在商業上使用我們的函式庫，請考慮付費。

這個時刻為使用者建立了一些摩擦，他們必須花一點時間考慮是否願意且能夠支持我們的函式庫。

## 借鑑 SaaS 的策略

我們決定希望那些從 React Flow 獲得價值且能夠輕鬆負擔的人成為財務支持函式庫的人。這意味著我們的大部分資金將來自組織，而不是個人。

我們希望每個開源支持者如果喜歡我們的函式庫，都會用公司的信用卡付款給我們，但在與訂閱者交談後，我們知道事情並非如此運作。他們通常必須向專案經理或技術長說明，詢問公司是否可以支持該專案。**我們作為開源創作者的工作，就是讓使用者更容易向他們的組織請求支持我們的專案。**我們可以透過借鑑 SaaS 的策略來做到這一點。

透過使用三欄定價頁面，持有信用卡的人在到達我們的定價頁面時，就能確切知道會看到什麼：左側便宜，右側昂貴。它說明了他們會得到什麼，以及需要花費多少。我們不需要解釋任何複雜的捐款結構，或者我們將如何確切使用他們的資金，我們認為這可能會成為那些能夠輕鬆負擔價格標籤的組織的障礙。透過這種方式，我們幫助使用者在組織內申請預算時成為成功的橋樑。

## 這並非新鮮事

投資者[非常清楚](https://nautacapital.com/insight/open-source-weathers-the-fundingstorm/)將開源作為商業模式的核心，因為這是獲得感興趣的使用者群體、專家回饋、開發者好感、潛在員工興趣，以及與採用你開源專案的大型公司建立關係的方式。沿著這條路，像我們這樣的函式庫的下一步可能是尋求投資，擴大我們的服務和／或專有產品，並最終尋求退場。

我們所做的則是有意保持小規模並緩慢成長。我們不想也不需要以超過核心函式庫成長速度的步伐擴大我們的專有產品。相反，我們可以獲得開源工作的報酬，**同時保有對函式庫發展方向的完全自主權**。

我們在此的建議是將投資者使用的模式應用於我們自己的開源專案，以便我們可以從公司和組織獲得報酬，而不是開源開發者付費給其他開源開發者的[封閉生態系統](https://stackoverflow.blog/2021/01/07/open-source-has-a-funding-problem/)。

## 效果可能因人而異

雖然我們認為許多人可以利用這些發現為他們的開源專案獲得更公平的報酬，但我們也承認我們在很多方面都有先機：在為網站標價之前，我們已經有一個準備就緒的業務（來自先前的代理工作），而且我們已經在函式庫上工作了兩年。我們很幸運地找到了一個處於許多新創公司建立節點式應用程式核心的利基市場，而建立視覺化函式庫使我們能夠在角落放置一個可見的標記，可以引導使用者訪問我們的定價頁面。

## 一些最後的想法

如果你不想從客戶那裡收錢，因為這會給你一種你不喜歡的責任感，那也沒關係。當你不僅有「使用者」，還有「客戶」時，需要做不同類型的工作，我們理解這一點。

以這種方式要求資金需要對我們工作的信心。要求為你可能認為是興趣愛好或不太嚴肅的專案收費可能很困難。僅僅因為我們「為了樂趣」或在「空閒時間」工作，並不意味著我們不應該獲得補償。如果我們都能為開源工作獲得補償，它甚至可能讓那些沒有[「空閒時間」特權](https://www.ashedryden.com/blog/the-ethics-of-unpaid-labor-and-the-oss-community)的人也能貢獻開源。

我們希望分享我們的旅程能夠幫助一些人將資金轉移到正確的人手中。
