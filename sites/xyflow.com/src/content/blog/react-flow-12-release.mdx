在過去幾個月裡，我們一直在為大家準備一個穩健的 React Flow 12 版本。自上次主要版本發布以來，我們的核心團隊已經成長到五人，在 Github 上獲得超過 22k 顆星，重新品牌化為 xyflow，推出了 Svelte Flow（其中許多優秀的副作用都融入了這個版本），並讓我們辦公室的所有植物都存活下來。

這個版本也帶來了「xyflow」拼圖的最後一塊，因為我們的套件名稱從 `reactflow` 更改為 `@xyflow/react`。我們保證短期內不會再更改套件名稱！

React Flow 12 自一月以來一直處於測試版，我們從那時起就一直在修復錯誤，所以我們有信心現在將其作為穩定版本發布。向那些已經試用並提交問題的勇敢者致敬，我們感謝你們！🙏🏻

如果你想跳過細節，直接遷移你的專案，請前往我們的[遷移指南](https://reactflow.dev/learn/troubleshooting/migrate-to-v12)。

## 1. 支援伺服器端渲染

<Bleed>
  <SSRFlow />
</Bleed>

<div className="text-center text-gray-500 mt-1">
  這個流程在伺服器端渲染。即使客戶端沒有 Javascript 也可以顯示。
</div>

React 正朝著伺服器端渲染的方向發展，像 [Nextjs](https://nextjs.org/)、[Astro](https://astro.build/) 和 [Waku](https://waku.gg/) 等工具。由於使用 React Flow 與這些工具的困難，我們已經多次被要求支援伺服器端渲染（[這裡](https://github.com/xyflow/xyflow/issues/3168)和[這裡](https://github.com/xyflow/xyflow/issues/3384)）。在 React Flow 11 中，Astro 預設在使用 React Flow 時只會渲染空白畫面，這不太好。

使用 React Flow 12，你現在可以：

- 為文件網站顯示靜態 HTML 圖表（即使客戶端沒有 JS）
- 動態生成開放圖表圖片，在分享流程連結時顯示為嵌入內容
- 為可爬取的內容預先渲染流程

查看我們的[伺服器端渲染指南](https://reactflow.dev/learn/advanced-use/ssr-ssg-configuration)

## 2. 計算流程 - hooks 和輔助函式

使用 React Flow 最困難的事情之一是管理狀態和資料流，儘管這實際上是 React 的普遍困難。

在新版本中，我們添加了輔助函式來簡化從連接的節點獲取資料、更新節點資料以及管理節點之間的資料。它不像完整的狀態管理那麼強大，但我們確信這可以幫助那些只需要在客戶端進行一些簡單資料處理的人更快地啟動並運行他們的 React Flow 應用程式。

查看我們的[計算流程指南](https://reactflow.dev/learn/advanced-use/computing-flows)

## 3. 深色模式

<Bleed>
  <RemoteCodeViewer
    route="examples/styling/dark-mode"
    showEditor={false}
    framework="react"
  />
</Bleed>

React Flow 終於內建了深色模式 🌚 我們添加了一個 `colorMode` 屬性，你可以在「light」、「dark」或「system」之間切換。在底層，React Flow 只是在包裝器中添加了一個類別名稱，但我們必須做很多更改才能實現這一點。現在所有預設樣式都使用 CSS 變數，因此你可以輕鬆地基於此建立自己的主題。

查看[深色模式範例](https://reactflow.dev/examples/styling/dark-mode/)

# 更多功能！

除了上面列出的新主要功能外，我們還添加了一些我們長期以來想要包含的其他功能。

- **[`useConnection` hook](/api-reference/hooks/use-connection)：** 使用此 hook，你可以存取正在進行的連接。例如，你可以使用它根據目前的起點／終點控制點為控制點著色或設計自訂連接線的樣式。
- **受控的 `viewport`：** 這是一個進階功能。可能的使用案例包括動畫化視窗或為低解析度螢幕四捨五入轉換等。此功能帶來兩個新屬性：[`viewport`](/api-reference/react-flow#viewport) 和 [`onViewportChange`](/api-reference/react-flow#on-viewport-change)。
- **[`ViewportPortal`](/api-reference/components/viewport-portal) 元件：** 這使得可以在視窗中渲染元素，而無需實作自訂節點。
- **[`onDelete`](/api-reference/react-flow#on-delete) 處理器：** 我們為 `onDeleteNodes` 和 `onDeleteEdges` 添加了一個組合處理器，使對刪除的反應更容易。
- **[`onBeforeDelete`](/api-reference/react-flow#on-before-delete) 處理器：** 使用此處理器，你可以防止／管理刪除。
- **[`isValidConnection`](/api-reference/react-flow#is-valid-connection) 屬性：** 這使得可以為所有連接實作一個驗證函式。它也會為程式化添加的邊呼叫。
- **[`autoPanSpeed`](/api-reference/react-flow#autoPanSpeed) 屬性：** 用於控制自動平移時的速度。
- **[`paneClickDistance`](/api-reference/react-flow#paneClickDistance) 屬性：** 觸發點擊的滑鼠按下／釋放之間的最大距離。
- **Background 元件：** 添加 [`patternClassName`](/api-reference/components/background#pattern-class-name) 屬性，以便能夠使用類別名稱設計背景圖案的樣式。如果你想用 Tailwind 設計背景圖案的樣式，這很有用。
- **Node Resizer 更新：** 當群組調整大小時，子節點不會移動，正確識別範圍和擴展
- **`onMove` 回呼** 會為函式庫呼叫的視窗更新（如 fitView 或放大）觸發
- **`deleteElements`** 現在返回已刪除的節點和已刪除的邊
- 為節點添加 **`origin` 屬性**
- 為邊添加 **`selectable` 屬性**
- 修正 `BezierEdge`、`StepEdge`、`SmoothStepEdge` 和 `StraightEdge` 元件的型別
- 函式庫建立的新邊只在設定這些屬性時才具有 `sourceHandle` 和 `targetHandle` 屬性。（我們過去會傳遞 `sourceHandle: null` 和 `targetHandle: null`）
- 當邊的 z-index 更改時，邊不會掛載／卸載
- 連接線知道目標控制點的位置，因此可以正確繪製路徑
- `nodeDragThreshold` 預設為 1 而不是 0
- 更好的選擇框可用性（在拖出流程時捕獲）
- 為 `NodeProps` 添加 `selectable`、`deletable`、`draggable` 和 `parentId`
- 當樣式未載入時添加警告
