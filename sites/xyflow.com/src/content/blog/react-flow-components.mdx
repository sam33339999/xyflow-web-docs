_**2025 年 7 月更新**：「React Flow UI」原名為「React Flow Components」。我們重新命名是因為它現在同時包含元件和模板。此外，由於它建構在 shadcn/ui 之上，「UI」這個名稱讓開發者更容易識別這個連結並理解我們提供的內容。以下文字已更新以符合新的命名。_

在 xyflow，我們非常注重使用我們的程式庫或文件時的開發者體驗：我們有大量的範例集合、從零開始引導您開發的教學，以及 [CodeSandbox 上的入門應用程式](https://codesandbox.io/p/sandbox/react-flow-starter-ts-r69228)。然而，一旦您轉移到自己的應用程式，這種出色的體驗就會開始消失。

我們的使用者一直很興奮地向我們展示他們正在建構的內容，隨著時間的推移，我們注意到許多 React Flow 專案在其流程中定義了類似的元件。這讓我們開始思考：我們如何減少大家正在做的重複工作，讓我們的使用者更容易快速上手？

## 最初的想法：為 React Flow 打造 UI 程式庫

我們的第一反應是建構一個配套的 UI 套件，提供一些預建的節點和邊緣。我們在這方面有一些經驗，我們的節點調整大小元件最初是一個獨立套件，之後才被整合到核心程式庫中。

表面上這聽起來是個好主意，但經過一番思考後，我們意識到採用這種方法有一個很大的缺點。與類似的程式庫相比，React Flow 被設計為相當低階並具有高度可客製化性。使用者如何客製化和設定隱藏在程式庫內部的元件樣式？

經過一番考慮，我們決定這種方法不適合我們，原因如下：

- 建構靈活、可重複使用且可以設定樣式並在不同應用程式中使用的元件會太複雜。

- 如果使用者需要我們未預期的功能，他們將不得不分叉元件程式庫並自己添加；這會否定我們開發程式庫的許多好處。

- React Flow 保持我們的主要焦點很重要，維護一個獨立的元件程式庫會佔用太多核心程式庫的時間。

## Shadcn 與元件程式庫的新方法

[Shadcn/ui](https://ui.shadcn.com) 是一個元件「程式庫」，一段時間以來一直在穩步獲得關注和採用。前提很簡單：shadcn 不提供不透明的元件套件，而是為每個元件提供原始碼，並期望您將程式碼嵌入到自己的專案中。這讓人想起 npm 和打包工具出現之前的日子，說實話感覺很不錯；當我們重建文件網站時，我們大量使用 shadcn 來處理許多 UI 元件。

這種方法感覺解決了我們發布獨立套件時遇到的許多問題，因此在年初，我們一些人開始著手建構一系列元件和程式碼片段，供大家嵌入到自己的專案中。

我們一直遇到的最大未解決問題是關於_樣式_該怎麼辦。一方面，我們想提供易於使用且開箱即用外觀良好的元件，但另一方面，我們無法對人們將採用的樣式方法做任何假設，而且我們無法輕易引入外部相依項目而不讓安裝過程變得混亂。

雖然我們擱置了這個想法，但它在我們的團隊會議中是一個經常討論的話題。我們知道發布_某些東西_的價值會很高，我們只是無法弄清楚_如何_做...

## 新希望：shadcn CLI

Shadcn 有一個簡單的 CLI 可以將他們的元件安裝到您的程式碼庫中已經有一段時間了，但最近 CLI 被賦予了安裝_外部_元件的能力，只要它們遵循簡單的 JSON 架構。

這為我們解決了一堆問題：

- 所有 shadcn 元件都使用 Tailwind CSS，因此我們可以為元件添加樣式，而無需擔心使用者安裝額外的相依項目。

- Shadcn 元件可以依賴_其他 shadcn 元件_，因此我們可以建構更複雜的元件，利用已經存在的優秀 shadcn 元件集合。

- 這些元件被嵌入到使用者的程式碼庫中，這意味著我們不需要擔心涵蓋每一個使用案例或功能請求：人們可以實作他們需要的東西！

## 介紹 React Flow UI

這就是我們再次投入專案所需的動力。我們一直在努力建構一系列初始元件，我們認為這將讓大家更容易組合 React Flow 專案。初始集合中的一些有趣元件包括：

- 一個[**資料庫架構節點**](https://reactflow.dev/ui/components/database-schema-node)，可以輕鬆視覺化表格和欄位之間的關係。

我們還為未來建構更進階的元件奠定了基礎。我們還不確定這是否是我們要承諾的事情，所以請試用這些元件並告訴我們您的想法！您可以前往 [reactflow.dev/ui](https://reactflow.dev/ui) 找到這些元件的文件和如何安裝它們的簡要指南，或者您可以[前往他們的文件](https://ui.shadcn.com/docs)了解更多關於 shadcn 和 CLI 的資訊。

我們很期待看到您使用這些元件建構的內容，我們期待聽到您的回饋！如果您遇到任何問題或對新元件有任何建議，請在我們的 [web 儲存庫](https://github.com/xyflow/web/issues)上開啟問題，如果您用它們建構了很酷的東西，一定要在 [@xyflowdev](https://x.com/xyflowdev) 上標記我們！
